## 4. 최강 모델 선정

### 🏆 1위 (채택): **M1 — 단순 단타 (전 자리 TP1 100%)**

- 복리 1년 리스크 1% 기준 **+34,979.8%** (= ×350 배)
- MaxDD 23.6% — 모든 모델 중 최저 동률
- avg R +0.207R/거래, Win 62.6% — 모든 지표 1위
- 위험조정 점수 1,482.2 — 2위 대비 +20% 우위

### 🥈 2위 (백업): **M2 — D 만 분할**

- 복리 +29,093.9%, MaxDD 동일 23.6%
- M1 대비 -17% 수익. D 자리 70건 (2.4%) 만 차이 → 영향 미미
- 만약 미래 D 자리가 더 자주 나오는 regime 이라면 M2 가 추월 가능 (현재 1년 데이터로는 M1 우위)

### 왜 분할 청산이 패배했는가 — 메커니즘 분석

1. **TP1 hit 후 본전 SL 의 비용** — 본전 SL 도 슬립 (entry 1bp + exit 1bp) + taker fee 0.06% =
   sl_d_pct 0.7% 기준 약 **-0.11R** 손실. 절반 잔여가 본전 SL 맞으면 -0.055R 추가 손실.
2. **TP2 (2.0R) 도달률 < 가정** — 1.236R → 2.0R 사이 되돌림 확률 높음. TP1 만 hit 후 본전 SL
   터지는 케이스가 분할 청산의 expected value 를 깎아먹음.
3. **Trail peak × 0.7 보수 가정** — 길게 끌어 +3R 가도 trail exit 은 +2.1R 평균. 슬립 + fee
   누적 → 단순 TP1 100% 대비 잔여 30~50% 에 대한 EV 가 음수가 되기 쉬움.
4. **D_capitulation 70건 (2.4%)** — 표본 너무 작아 통계적 우위 미입증. M2 vs M1 차이는
   D 70건 표본의 잡음 범위 (CI 넓음).
5. **PREMIUM 분할 (M3/M6)** — PREMIUM 자리 (684건) 에 TP1 50% + TP2 50% 적용 → 본전 SL
   비용 + TP2 미달 케이스 손실이 단순 TP1 100% 대비 -0.038R/거래 깎음.
6. **다이버+4H 자리 3분할 (M4/M5)** — 길게 끌수록 길게 끄는 가정의 비용 (시간 보유 = 펀딩비 +
   path 노이즈) 이 누적. 660건 표본에서도 단순 단타가 우위.

## 5. 봇 적용 코드 가이드

### 5.1 권장 운영 — M1 채택 유지

기존 v1.15 이미 M1 (TP1 전량) 채택 상태 → **변경 불요**. 단, 봇 코드에 청산 로직이 명시적으로
박혀 있는지 점검 필요.

### 5.2 봇 코드 확인 포인트

`krtky_alert_bot.py` 는 알림만 발송하는 봇이므로 청산은 사용자가 수동/거래소 OCO 로 처리.
알림 메시지에 `TP1 100% 청산` 명시 (이미 v1.15 적용됨).

`build_entry_signal()` 의 메시지 템플릿 (해당 함수 grep):

```python
# 예시 적용 코드 (1.236R 단일 TP)
def make_exit_plan(entry: float, sl: float, direction: str) -> str:
    sl_d = abs(entry - sl)
    if direction == "long":
        tp1 = entry + sl_d * 1.236
    else:
        tp1 = entry - sl_d * 1.236
    return f"TP1 (1.236R) {tp1:.4f} — 전량 청산 (M1 백테스트 1년 1위, 복리 ×350)"
```

### 5.3 만약 사용자가 직접 분할 청산 선호한다면

백테스트 결과로 보면 **분할 청산을 모두 비추천**. 그래도 굳이 시장 유형별 분기를 원한다면:

- **M2 (D 만 분할)** 만 차선책. 다른 분기 (M3~M6) 는 EV 깎임 폭이 더 큼.
- 적용 코드 — `krtky_alert_bot.py` 의 알림 직전에 `detect_market_type()` 호출하고 D_capitulation
  일 때만 메시지 템플릿을 "TP1 50% + 잔여 trail" 로 분기:

```python
# build_entry_signal() 내부 — 청산 플랜 분기 (M2 채택 시)
market_type = detect_market_type(closed_15m)
if market_type == "D_capitulation":
    exit_plan = (f"TP1 50% @ {tp1:.4f} (1.236R) + 잔여 50% 본전 SL + Trail "
                 f"(D 자리 길게 끌기, M2)")
else:
    exit_plan = f"TP1 100% @ {tp1:.4f} (1.236R) 전량 청산 (M1)"
```

### 5.5 다음 검증 항목 (후속 작업)

1. **D 표본 확장** — 70건은 통계 신뢰도 부족. 2~3년 데이터 또는 다른 거래소 (Bybit) 추가로
   D_capitulation 만 200건+ 확보 후 M2 vs M1 재측정.
2. **부분 청산 비용 가정 완화** — 본전 SL 슬립 0.08% 가정이 보수적 가능. 라이브 OCO 로 본전+ε
   SL 잡으면 슬립 절감 가능 → 재시뮬.
3. **Regime split** — 강세장 1년 vs 박스장 1년 따로 보면 D 분할이 박스장에서 우위일 수도. 현재
   1년 데이터는 강세 + 박스 혼재 → split 후 재측정 권장.
4. **TP1 수준 sensitivity** — 1.236R 외에 1.0R / 1.5R / 1.764R 도 측정해서 진짜 최적 TP 자리
   탐색 (현재는 크보나치 1.236 고정).
