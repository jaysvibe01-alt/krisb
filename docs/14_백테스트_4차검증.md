### 결함 #6 — 자본 회전율(capital turnover) 가정 오류 — **확정 (심각)**

코드 `backtest_compound_returns.py:71-75`:

```python

    r = t["final_r"]
    capital *= (1 + (risk_per_trade_pct / 100) * r)
```

`compound_simulation`은 거래 리스트를 **단일 자본 스레드**에 시간순으로 곱한다.
즉 거래 i 가 끝나면 즉시 거래 i+1 에 100% 자본을 다시 투입.

라이브 차이:
- M1(29종 2911건) 기준: 365일 / 2911건 = **거래간 평균 간격 3.0시간**.
- 실제 봇은 진입 알림 → 매수존 limit 대기(평균 30분~12시간) → 체결 → MAX_HOLD_BARS=48봉(=12시간) 보유.
- **`MAX_HOLD_BARS=48` (`backtest_realistic_pnl.py:50`) = 12시간**. 거래간 평균 3시간 < 보유 12시간 → 라이브에서는 모든 거래가 다음 거래 시작 전에 끝날 수 없다.
- 시뮬은 이를 무시하고 모두 다음 거래에 즉시 재투입 → **자본 회전율을 4배 이상 부풀림**.

라인 증거: `backtest_compound_returns.py:71-82` `history`에 active 큐 / `hold_bars` 체크 일절 없음.

## 5. 즉시 수정 권장 1개

### 최우선: `backtest_compound_returns.py:compound_simulation` 에 active 큐 + max_concurrent 도입

현재 (L51-96): 단일 자본 스레드, 즉시 재투입.

수정안 (의사코드):
```python
def compound_simulation(trades, risk_per_trade_pct, max_concurrent=2,
                       starting_capital=100.0):
    capital = starting_capital
    active = []  # [(end_ts, allocated_capital_pct)]
    n_skipped = 0
    history = [capital]

    for t in trades:
        ts = t["bar_ts"]
        # 종료 정리
        finished = [(e, alloc, r_pending) for e, alloc, r_pending in active if e <= ts]
        for end_ts, alloc, r_pending in finished:
            capital *= (1 + (risk_per_trade_pct / 100) * r_pending * alloc)
        active = [(e, alloc, r_pending) for e, alloc, r_pending in active if e > ts]

        if len(active) >= max_concurrent:
            n_skipped += 1
            continue

        # 동시 한도 N → 자본 1/N 분할
        alloc = 1.0 / max_concurrent
        hold_ms = t.get("hold_bars", 12) * 15 * 60 * 1000
        active.append((ts + hold_ms, alloc, t["final_r"]))
        history.append(capital)

    # 잔여 active 청산
    for end_ts, alloc, r_pending in active:
        capital *= (1 + (risk_per_trade_pct / 100) * r_pending * alloc)

    return {..., "n_skipped": n_skipped, ...}
```
